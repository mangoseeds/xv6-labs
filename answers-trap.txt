5. What is the output of the given code?
-> HE110 World
57616 in hex is 0xE110
0x00646c72 in memory is stored as 72:(ASCII) r, 6c:l, 64:d, 00:\0 (ordered by lower to higher address)
Little endian stores lower significant byte first, so it prints rld.
For big endian, i has to be set differently.
i = 0x726c6400 would be 00:\0, 64:d, 6c:l, 72:r, and big endian will store bytes from higher address.

6. What is going to be printed after 'y='? Why does this happen?
-> some garbage value
printf will expect two integer arguemts, given two %d format specifiers, but the given code shows only one arguemnt.
Therefore, printf will use whatever value happens to be in the register that would have held the second argument. This value is unpredictable.
This happens because printf doesn't actually know how many arguments were actually passed, but merely reads from the registers where the argumens should be.
